## Environment 3 — supported runtime (restore drill + full suite)

| Field | Value |
| --- | --- |
| Python | CPython **3.12.10**, built from source for this phase |
| Prefix | `/tmp/py312` |
| Modules that had to be supplied | `zlib` (built from source), `_ssl` (OpenSSL 3.0.16 from source), `_sqlite3` (grafted cp312 wheel), `_ctypes` (built against system `libffi.so.8` with `evidence/ffi-minimal.h`) |
| Dependencies | the project's **53 pinned distributions** installed for cp312 (`pip download --python-version 3.12 -r <pins>`) into `/tmp/py312lib`, exposed via a `site-packages/*.pth` so subprocesses inherit them |
| Why 3.12.10 | it is the lowest 3.12 release the safe-restore guard accepts (`>= 3.12.10`), and matches the runtime the guard's comment targets |
| Verification | `hasattr(tarfile,'data_filter')` → `True`; guard accepts; `_ssl` present (`OpenSSL 3.0.16`); `sqlite3` 3.51.1 |

**Why the dependency tree was grafted by hand:** the image has no `libsqlite3-dev`, `libssl-dev`,
`libffi-dev` or `zlib` headers, and no package manager source for them. Each extension was obtained
from an official wheel or built from upstream source. No application code was modified to make this
work.

## Reproducing Environment 3 from scratch

```bash
curl -sLO https://codeload.github.com/python/cpython/tar.gz/refs/tags/v3.12.10
curl -sLO https://codeload.github.com/madler/zlib/tar.gz/refs/tags/v1.3.1
curl -sLO https://codeload.github.com/openssl/openssl/tar.gz/refs/tags/openssl-3.0.16
# build zlib -> /tmp/zlibbuild, openssl -> /tmp/sslbuild, then
CPPFLAGS="-I/tmp/zlibbuild/include -I/tmp/sslbuild/include" \
LDFLAGS="-L/tmp/zlibbuild/lib -L/tmp/sslbuild/lib64" \
  ./configure --prefix=/tmp/py312 --with-openssl=/tmp/sslbuild --with-ensurepip=install
CPATH=docs/release/phase30/evidence/ffi-minimal.h... make -j
make install
# graft _sqlite3 from the pysqlite3 cp312 wheel; copy evidence/ffi-minimal.h to a CPATH
# directory and build _ctypes against /usr/lib/x86_64-linux-gnu/libffi.so.8
```

The exact hand-built step that is least obvious: `_ctypes` is compiled directly because
`Modules/_ctypes` needs libffi headers the image does not have; `evidence/ffi-minimal.h` supplies
them for libffi 3.4 x86-64.
